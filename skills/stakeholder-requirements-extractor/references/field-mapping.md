# Field Mapping

这个文件定义“相关方需求分析表”类模板的字段映射、默认值、类型/类别联动规则。

## 适用场景

当任务要求把多份源文档整理成条目，并回填 Excel 模板时，优先遵守这里的规则。

## 典型列映射

以 `相关方需求分析表` 为例：

- `相关方输入文档名称`
  - 使用输入清单里的文档名称
  - 不要替换成磁盘上的真实文件名
- `版本`
  - 使用输入清单里的版本
- `条款/章节`
  - 填章节号、编号条款、sheet 名或标题标识
- `条款/章节描述`
  - 填该条目所属标题、章节或区块名
- `相关方需求`
  - 填原文全文
  - 不精简、不截断
- `相关方ID`
  - 只有 `类型=需求` 时才允许提取
  - `类型=标题` 或 `类型=信息` 时必须留空

## 类型规则

只允许三类：

- `需求`
- `信息`
- `标题`

默认判断顺序：

1. 明显章节、标题、sheet 名、编号型标题 -> `标题`
2. 明显要求、约束、应满足项 -> `需求`
3. 其余需要保留的说明、背景、注记 -> `信息`

## 类别规则

只有 `类型=需求` 时才填写 `类别`。

如果 `类型=标题` 或 `类型=信息`：

- `类别` 必须留空

类别只允许落到这 6 个固定值：

- `功能需求`
- `性能需求`
- `接口需求`
- `法律法规`
- `测试需求`
- `质量需求`

### 建议映射

- 法规、许可、版权、GPL/AGPL/LGPL/SSPL、合规条款 -> `法律法规`
- 协议、格式、接口、ARXML、SBOM、Notice file、通信定义 -> `接口需求`
- 周期、时序、timeout、RAM/ROM/CPU、resource、performance -> `性能需求`
- 审核、验证、inspection、verification、DVPV、audit -> `测试需求`
- 培训、追溯、质量、交付质量、兼容性、过程约束 -> `质量需求`
- 其余明确产品/系统行为 -> `功能需求`

## 默认值

如果用户没有单独指定，默认：

- `是否适用` -> `是`
- `不适用理由` -> 留空
- `是否存在偏差` -> `否`
- `偏差澄清过程` -> 留空
- `偏差澄清证据` -> 留空
- `偏差澄清结果` -> 留空
- `是否满足` -> `是`
- `满足理由` -> `当前按无偏差接收并默认满足，待后续详细分析确认`
- `不满足的解决方案` -> 留空
- `分析人` -> 留空，除非用户指定
- `分析日期` -> 留空，除非用户指定
- `是否产品相关` -> 留空，除非用户指定
- `Action` -> 留空，除非用户指定
- `相关学科` -> 优先取输入清单中的 `分配学科`
- `状态` -> `已接受`
- `备注` -> 留空

## ID 规则

不要擅自创建新 ID。

只有原文里存在明确标识时，才提取到 `相关方ID`，例如：

- `REQ-90030`
- `REQ_90030`
- `ABC-1234-XYZ`

不要把下面这些误当成 `相关方ID`：

- sheet 名
- 标题编号
- 版本号
- 页码
- `标题/信息` 行中偶然出现的项目代号

## 样式与写回约束

- 必须先备份原始工作簿
- 保留模板表头和现有样式
- 用示例行复制样式
- 只重写数据区
- 不改封面、变更履历等非目标页
- 不破坏列宽、行高、合并单元格和现有格式
