# SRS 缺口盘点报告 / Gap Report

**目标**：把《多功能制氧机系统需求 V1.0_20260513-release》转写成符合公司模板
`AU-QR-R&D-027 软件需求规范 (SRS) V3.0` 的软件需求规范。

**结论先行**：现有系统需求文档（SysReq）覆盖了"产品/系统层"的功能描述与流程，但 SRS 模板要求的是
**软件层 (Software)** 的、可分配到 SWC/可验证的原子需求。两者之间存在系统性缺口。
另外项目目录里其实已经有若干**补充文档可直接利用**（见第 3 节），但仍有关键输入缺失（见第 1 节）。

## 1. 必须补齐才能写出完整 SRS 的缺口（高优先级）

### 1.1 软件层原子需求（最核心缺口）
- SysReq 用"功能概述 + 基本流程"描述功能，全文只有 **31 个系统级 SR-xx-xxx ID**，**没有可分配到 SWC 的、可验证的软件需求**。
- SRS 模板每条需求需要：`Req ID / Title / Description("shall"句式) / Type / Maturity / Variant / Assignation(SWC) / Test by / ASIL / Feature / Verification Criteria / Covered Req(上溯) / Release Plan`。
- **缺**：把每个功能流程拆解为软件 shall-需求的"派生规则/拆解粒度约定"，以及谁负责评审需求成熟度（Maturity）。
- 可由我在起草时**派生**，但需要确认：软件需求 ID 前缀（模板示例为 `HOD_SRS_SWC_xxx`，制氧机项目用什么前缀？）。

### 1.2 信号映射的精确数值（Signal Mapping）
- 模板"软件外部接口及信号映射"和每条 SWC 需求要求字段：`Name / Type / Range / Unit / Description / Source / Destination`，并要求采样周期等（如示例"every 5ms"）。
- SysReq 有接口/引脚/硬线信号类型定义，但**缺少软件视角的逐信号清单**（每个信号的工程量程、单位、ADC/数字类型、采样周期、刷新率、默认值）。需要从 HSI 端口定义 + MCU 管脚 + HSR 交叉整理，**但其中"采样周期/刷新率/滤波/去抖时间"通常未在这些文件里给全**。

### 1.3 实时约束（Real Time Constraints）的量化指标
- SysReq 有"响应时间/CPU 负载/运行时间限制"章节，但 SRS 需要**任务级时序**：各 SWC 周期任务节拍（如 1/5/10ms task）、调度方式、各信号采样周期、关键功能端到端时延预算。这些目前缺。

### 1.4 非易失性存储 / Data Flash 内容（NVM）
- 模板有独立章节"非易失性存储器内容 / Data flash Content definition"（字段：Signal Name / Description / Type / ID / Value / Unit / Rational）。
- SysReq 全文 **0 处**提到 NVM / 非易失 / data flash。需要：哪些标定值、故障码、运行统计、用户设置需要掉电保存？其默认值与存储布局？

### 1.5 Bootloader / 通讯管理 / 诊断 的软件细节
- 模板有"引导程序 Bootloader""通讯管理 Communication Management"章节。SysReq **0 处**提 Bootloader/刷写流程；CAN↔UART 协议有，但 **UDS 诊断服务列表、DTC 清单、刷写时序** 缺（虽引用了 UDS/Flash Programming 测试规范，但规范文档本体不在项目内）。

### 1.6 功能安全 (ASIL) 与网络安全 (Cybersecurity)
- SysReq 中"功能安全""网络安全"两章均标注 **（预留）**，正文为空；ASIL 仅出现 1 次。
- 模板需要：功能清单的 ASIL 等级、安全机制、安全相关软件需求；以及 Cybersecurity 需求（如 SecOC，全文 0 处）。
- **缺**：HARA/安全概念文档、TARA/网络安全概念。若项目判定为 QM（无安全等级），需要一份书面确认。

## 2. 中/低优先级缺口（影响完整度但可标 TBD 推进）

| 项 | 模板要求 | SysReq 现状 | 需补什么 |
|---|---|---|---|
| 软件变体 (SW Variants) | 软件变体管理章节 | 有 HW 配置，软件变体未定义 | 是否一套软件覆盖多硬件/市场？变体维度清单 |
| 功能间接口 (Interface between features) | 各 feature 间输入输出耦合表 | 流程分散，未画 feature 交互 | 由我从流程推导，需评审确认 |
| 各功能在功能模式下的适用性 | feature × 功能模式 矩阵 | 有电源状态(KL30/运行)，未做矩阵 | 完整的软件功能模式定义 + 适用性矩阵 |
| 资源约束数值 | RAM/ROM/Stack 预算 | 有"资源限制"标题 | 具体 RAM/Flash/Stack 数字 |
| 编码/命名/文件命名规范 | 模板有专门小节 | 未在 SysReq 内 | 公司 C 编码规范、MISRA 版本、命名规则文档 |
| 设计规范 / 可靠性 | Design Rules / Dependability | 有可靠性/可维护性等定性描述 | 量化指标（MTBF、复位策略、看门狗策略——全文 0 处看门狗） |
| 术语表 / 缩写 | 模板要补全 | SysReq 有 18 项缩写表 | 大部分可复用，需对齐软件特有术语 |
| 参考/适用文件 | 模板分 References + Applicable docs | SysReq 有 10 项参考表 | 多份为外部规范（YY/GB/NIO-TS），**文档本体不在项目内**，只能引用编号 |

## 3. 缺口来源对照（哪些能就地补、哪些必须外部提供）

**A. 可由我从现有补充文档整理/派生（不需额外人工输入）**
- 软件功能清单、产品/软件总览、HW 变体、MCU 型号、信号清单骨架、上溯 ID（产品需求 V2.0 已在目录中）。

**B. 现有文档里可能有、需打开核对（本报告未逐格读完表内数值）**
- HSI 端口/管脚的逐信号量程与类型、外围负载驱动参数、开发计划里的发布计划与功能-需求映射。

**C. 必须由人/外部文档提供，否则只能标【TBD】**
1. 软件需求 ID 命名前缀与拆解粒度约定
2. 各 SWC 任务节拍 / 采样周期 / 时延预算（实时约束量化）
3. NVM / Data Flash 内容定义（掉电保存项、默认值、布局）
4. Bootloader / 刷写流程；UDS 服务与 DTC 清单
5. 功能安全 ASIL 判定（HARA/安全概念）或"QM 无安全等级"书面确认
6. 网络安全需求（TARA / SecOC 等）
7. RAM/ROM/Stack 资源预算、看门狗/复位策略
8. C 编码规范 / MISRA 版本 / 命名与文件命名规范
9. 软件变体维度定义
10. 完整软件功能模式定义及"功能×模式"适用性
11. 被引用的外部规范本体（通信矩阵 v1.0、UDS/Flash/CAN 测试规范、YY/GB 标准）—— 仅有编号，无文件
