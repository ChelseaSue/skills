# 三份交付物的列契约

以下列布局核对自公司模板与**已评审通过的真实交付物**（`BBS_P519_V436` 系列）。
模板给骨架，真实交付物给粒度与文风——两者不一致时以真实交付物为准，并在此记录差异。

## 1. 软件单元测试用例（AU-QR-R&D-046）

原始模板是 `.xls`，openpyxl 无法写入，因此按本契约重建为 `.xlsx`。

**组织方式**：**一个模块一个 sheet**，sheet 名即模块名（真实交付物有 25 个模块 sheet）。

**表头占 5 行**（第 1 行测试级别，第 2~4 行说明，第 5 行列标题），数据从第 6 行起。

| 列 | 标题 | 取值 |
|---|---|---|
| 1 | 模块/Module | `ut_spec.component` |
| 2 | 优先级/Priority | `H` / `M` / `L`，由 SWDD `Priority = Complexity × Importance` 按 `priority_map` 映射 |
| 3 | 标识符/Flag | 用例 ID，如 `SUT-00001` |
| 4 | 名称/Name | `{函数名}.{三位序号}`，如 `O2_DriveTiming.003` |
| 5 | 软件单元ID | SWDD `2.4.2` 的 Unit ID |
| 6 | 软件单元名称 | 函数名 |
| 7 | 测试方法/Test Method | 取自 `test_methods`，默认「功能测试」 |
| 8 | 设计方法/Design Method | 说明用例的设计思路与取值过程 |
| 9 | 测试目标/Test Target | **「覆盖分支 N/M」** —— N/M 为 SWDD 流程图的分支编号 |
| 10 | 预置条件/Precondition | 测试环境与初始化 |
| 11 | 测试步骤/Test Steps | 逐条列出输入设置，**每条以 `--N` 标注命中的分支** |
| 12 | 预期输出/Expect Output | 期望的返回值与副作用 |
| 13 | 判定准则/Criteria | 固定话术，取自 `verdict_default` |

**合并单元格约定**：同一函数的连续多行，**只在首行填第 5、6 列**，其余行留空。
真实交付物即如此（`BBSM_bHasVoltageFault.002` 有 unit id，`.001` 无）。

**右侧列（15 列往后）**：真实交付物在此嵌入覆盖率截图，按函数名分组，这是那份文件达到 21MB 的原因。
本 skill **不嵌截图**，改在报告中引用 gcovr HTML 路径。

## 2. 软件单元测试报告（AU-QR-R&D-048）

模板 sheet：`封面Cover` / `模板修订记录` / `文档修订记录` / `报告SW unit verification summary` /
`静态验证结果Static validation results` / `填写说明`。克隆模板，只重写后两个。

`报告` sheet 的五个总结区：

1. **测试目标总结** —— 目标 / 工具 / 实际达成 / 达成判定 / 未达成说明。
   真实交付物的目标行：100% 覆盖详设、100% 语句覆盖、100% 分支覆盖、代码评审关闭率 100%、
   用例执行率 100%、测试通过率 100%、缺陷关闭率 100%、圈复杂度 ≤15、编码规则无高风险项。
2. **静态验证情况总结** —— 可分多轮；每轮记录对象版本、验证项、通过标准、结果说明、是否通过。
   真实交付物做了三轮，判定用了 `Pass` / `Pass with conditions` 两种。
3. **覆盖率情况总结** —— 按被测对象列语句/分支/MC-DC 与是否达标。
   **MC/DC 在 ASIL QM 时填「不适用」**，不要填 0。
4. **测试实施情况总结** —— 轮次 / 对象 / 选择用例数 / 执行数 / 未执行数及理由 / 通过数 / 执行率 / 通过率。
5. **缺陷解决情况总结** —— 发现 / 修正 / 未修正数量与整体分析。

**差异记录**：真实交付物比模板多一个 `issue` sheet（152 行缺陷明细）。
本 skill **按模板不生成该 sheet**，缺陷另行管理。

## 3. 软件单元测试追溯矩阵（AU-QR-R&D-038）

模板 sheet：`封面` / `模板修订` / `修订履历` / `正向` / `反向`。克隆模板，只重写后两个。

**正向（用例 → 详设）**：序号 / 用例ID / 用例名称 / 详设ID / 详设名称 / 备注

**反向（详设 → 用例）**：序号 / 详设ID / 详设名称 / 用例ID / 用例名称 / 备注
同一详设单元的多条用例，**只在首行填详设 ID 与名称**。

**数据统计区**（两个 sheet 都有，放在右侧 H/I 列）：

| 统计项 | 含义 |
|---|---|
| 软件单元测试用例数量 | 用例总数 |
| 软件详设单元数量 | SWDD `2.4.2` 的单元总数 |
| 追溯的软件详设数量 | 至少有一条用例的单元数 |
| 软件详设覆盖率 | 上两者之比 |

**差异记录**：真实交付物用的文件编号是 `AU-ASPICE-R&D-SUP.1-T06`，ID 前缀是 `SUT-`（模板写 `SWUT-`）。
模板 V1.2 的修订说明写着"为不同过程域拆分成对应文档"，应即此拆分的结果。
ID 前缀由 `ut_spec.id_prefix` 配置，不写死。

## 写 Excel 时的一个坑

克隆模板后必须**先解除合并单元格再写入**。openpyxl 对合并区域中非锚点单元格的写入会
**静默丢弃**，表现为零散几行数据凭空消失且不报错。
`build_deliverables.py` 的 `_reset_sheet()` 已处理：先 `unmerge_cells` 再 `delete_rows`。
