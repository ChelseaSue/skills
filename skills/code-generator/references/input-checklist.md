# 输入清单与缺口提示（第 2 步必做）

代码生成前先盘点输入。SRS 说"做什么"、SAD 说"怎么搭"，但**从架构到能跑的代码之间，还有一层实现级信息**——
这层信息 SAD 里常常不全，闷头生成只会硬编造或静默留洞。所以**先点名缺什么，请用户补充或确认默认**。

## 必需 / 建议 / 实现级 三类输入

| 类 | 输入 | 为什么 | 缺了怎么办 |
|----|------|--------|-----------|
| 必需 | **SAD（软件架构）** | 主驱动：定层、定模块、定接口、定状态机/时序 | 没有就无法生成——请用户先用 `sad-generator` 产出或提供 |
| 必需 | **SRS（软件需求）** | 每条需求要落到模块/函数并追溯；逻辑取值来源 | 缺则无法做 100% 追溯——请用户提供 |
| 必需 | **基础 SDK 代码根** | 生成代码要对接的 BSP/MCAL/OS/RTOS/已有驱动接口 | 缺则 HAL 实现层无处落地——请用户给代码根路径 |
| 建议 | **通信矩阵 / DBC** | CAN 收发逻辑对接真实报文/信号/周期/收发方向 | 缺则总线信号用 `TBD` 占位，标注待补 |
| 建议 | **MISRA C:2012 PDF** | 规则权威；日常用 cppcheck 自动门禁 | 缺则按 `misra-c2012.md` 速记清单 + cppcheck |
| 参考 | 系统需求 / 产品需求 / HSI 管脚定义 | 实现级信息（管脚、时钟、外设实例）的来源 | 见下方"实现级信息"逐项点名 |

## 实现级信息（SAD 里常缺，必须点名问，别硬编造）
生成前对照目标模块逐项确认；缺的列进缺口清单：
- **管脚 / 端口映射**：GPIO/外设到 MCU 引脚的实配（以 HSI/PINMUX 为准，不是 SAD 草图）。
  - ⚠️ **板级网络名（HSI 的 "PIN define" 列，如 `Cap1_V_ADC`/`MOS_CTR1`/`AFE_SCL`/`D1_IN1`）只有原始 HSI
    表里有**——SRS 的引脚总表通常只还原"MCU 侧功能名 + 功能描述 + 追溯 ID"，**会丢掉板级网络名列**；SAD 更只做
    外设级摘要、引几个代表引脚并指回 SRS。所以代码要用这些网络名做引脚常量命名/接线注释/与原理图对照时，
    **直接读 HSI xlsx**（用 openpyxl 读"PIN define"列），别指望 SRS/SAD 有。SRS §引脚总表适合拿"引脚↔功能↔需求"
    的对应，HSI 适合拿"引脚↔板级网络名↔方向"。两者互补，缺一会留洞。
- **时钟 / 分频 / 波特率**：系统时钟、外设时钟、CAN/SPI/I2C/UART 速率。
- **外设实例号**：用哪个 ADC/PWM/CAN/SPI 实例与通道。
- **任务划分**：任务优先级、栈深、周期（10ms/100ms…），中断优先级。
- **定时 / 节拍**：tick 周期、超时阈值、去抖时间——很多在 SRS/SAD 有，核对清楚。
- **缓冲 / 队列尺寸**：收发缓冲、信号池容量、事件队列深度（编译期常量，进 `_Cfg.h`）。
- **NVM 布局**：哪些参数掉电保存、块大小、默认值、读写时机。
- **返回码 / 错误码取值**：统一 `Types` 里的枚举取值与语义。
- **CAN 报文细节**：报文 ID、周期、收发方向、信号位布局（来自通信矩阵）。

## 给用户的缺口提示输出范例
> **代码生成前的输入盘点（请确认）**
>
> 已找到：✅ SAD（`软件架构/xxx.md`）✅ SRS（`软件需求/xxx.md`）✅ SDK 代码根（`code_git/Source`）✅ 通信矩阵（`dbc/xxx.dbc`）
> 缺失/待确认：
> 1. ⚠️ ADC/PWM 管脚映射未在 SAD 给全——可提供 HSI/PINMUX 表，或确认我按 SAD 草图占位（标 TBD）？
> 2. ⚠️ 任务优先级/栈深未定——按"10ms 高于 100ms、栈各 512 字"默认假设可否？
> 3. ⚠️ NVM 块布局未定——本次先不实现持久化、留接口桩可否？
> 已确认范围（不再追问）：功能安全本期不涉及；通信矩阵已就绪。
>
> 请补充上述信息，或回复"按默认/TBD 继续"。

把已确认的范围决定记在清单顶部，避免反复追问；缺口处生成代码时统一用 `/* TBD: 待补充<具体内容> */` 标注，
**绝不硬编造寄存器值/管脚/魔法数**。
