# 交付物格式

## 协议符合性矩阵（xlsx）

| 工作表 | 内容 |
|---|---|
| 符合性矩阵 | 全部检查项（含不适用及理由），按标准、条款排序 |
| 统计 | 每份标准的检查项数与各结论数、符合率；合计行 |
| 发现项 | `findings` 中登记的观察（有登记时才生成） |
| 不符合项 / 转SWE.6-HIL / 未检查 | 对应结论的筛选视图 |

列：检查项ID、标准、版次、条款、标题、要点（自述）、方法、适用、结论、证据、结论来源（applicability/static/host/review/method）、
原文核对（已核对/未核对）、页码。

## 检查报告（md）

1 结论摘要（总数、适用数、各结论数、符合率）→ 2 标准与适用范围（每份标准适用条款数与符合率）→ 3 不符合项（含证据）→
4 未检查项 → 5 转 SWE.6/HIL/一致性测试的条款 → 6 发现项 → 7 条款核对状态 → 8 说明。

## 证据附注与发现项（std_project.json）

- `notes`：`{检查项ID: 文字}`，附加在该条证据之后，写根因所在模块和整改建议；不改变结论。每条“不符合”都应有 note。
- `findings`：`[{id, topic, detail, related:[检查项ID]}]`，登记不针对某一条款下结论的观察：越层依赖、配置了但没被使用的参数、
  功能实际在应用层实现、配置副本漂移（`host probe` 的 `[drift]`）等。测试过程中一发现就登记，不要只写在测试注释里。

## 计数口径

- 符合率 = 符合 ÷（符合 + 不符合 + 未检查）。未检查留在分母里，未完成的检查不会抬高符合率。
- 不适用、转 SWE.6/HIL 不计入分母，但在矩阵中逐条列出理由。
- 一条检查项只有一个结论；多个测试共同支撑一条检查项时，全部通过才算符合。
