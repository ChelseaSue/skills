# 输入缺口清单（SRS 各章节需要什么 / 缺了怎么提示）

第 2 步"缺口提示"用这张表。对每一项判断：**已找到**（指出来自哪个文件）/ **部分**（有但不全，说明缺的维度）/
**缺失**（请用户补充，或说明将用 TBD 兜底）。给用户的提示要具体——不要只说"缺信息"，要说缺哪一项、
影响 SRS 的哪个章节、能否先用 TBD 占位继续。

约定：
- **能 TBD 兜底**＝该信息缺失不阻断起草，先写 `【TBD-待补充：…】`，不影响其余章节。
- **建议先补**＝缺了会让大段内容变成空壳或编造（如 ASIL、软件架构），强烈建议用户先给，否则明确告知该章节多为占位。
